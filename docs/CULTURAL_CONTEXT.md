# Cultural Context and Terminology

## Source and Attribution
This project is inspired by Dr. Jennifer Grenz's book *Medicine Wheel for the Planet*. The ideas that inspire it are **relationality**, **reciprocity**, and the book's critique of treating ecosystems as fixed, static equilibria.

Read the book itself. This repository is not a summary of it and cannot stand in for it.

## What This Project Is
- An educational engineering framework written from an IT practitioner's perspective.
- The author's own interpretation of a few general principles as software and team practices.
- A set of metrics, templates, and practices that any IT team can adapt.

## What This Project Is Not
- It is not a description or teaching of any Nation's knowledge, ceremony, or protocol.
- It is not endorsed by Dr. Grenz or by any Indigenous community or organization.
- It is not a cultural training resource.

## Positionality
The author writes as an IT practitioner and learner, not as a knowledge holder. Readers should treat the direction mapping and all metrics as engineering choices made for this repository.

## The Four Directions in This Repository
The North / East / South / West layout is an **organizing device** for grouping engineering concerns. The themes assigned to each direction are the author's own and are not claimed to match any specific teaching.

| Direction | Engineering theme in this repo |
|---|---|
| North | Historical records and baselines |
| East | Interdependence and variance |
| South | Continuous tending (maintenance) |
| West | Relational governance (review) |

## Terminology Guide
The aim is to use plain, established IT vocabulary. Borrow principles, not sacred or ceremonial terms.

| Use | Avoid | Why |
|---|---|---|
| Historical records, baseline | Ancestral memory, ancestral heritage | Ancestry carries cultural and spiritual meaning beyond system history |
| Tending, maintenance, stewardship | Ceremony, ritual, smudge | Ceremonial terms are not metaphors for engineering tasks |
| Systemic disruption, overload | Trauma | Trauma carries real, lived weight |
| Reciprocity, balance | Harmony with spirit, sacred balance | Keep claims technical and measurable |
| Team load, operational burnout (aggregate) | Individual burnout scores | Protects people; see [team load check](templates/team-load-check.md) |
| Knowledge holders, communities | Generic "Indigenous wisdom" | Knowledge is specific to peoples and places |

Before adding new labels, ask: *Would this term make sense to an IT reader without cultural borrowing?* If not, choose a plainer term.

## People and Data
The `knowledge_equity` and `operational_burnout` dimensions are about people. Apply these rules:
- Collect team-level, anonymous input only.
- Report aggregates; never rank or compare individuals.
- Tell the team what is collected, why, and who sees it.

If your project handles data about Indigenous peoples or communities, follow their data governance expectations. Useful starting points are the CARE Principles for Indigenous Data Governance (Global Indigenous Data Alliance) and, in Canada, the First Nations principles of OCAP® (First Nations Information Governance Centre).
